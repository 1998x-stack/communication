# 同事协作：教学与教练参考

> 本文是本项目归纳的训练设计，不表示原研究机构认证这些具体参考话术。

## 教学目标
将模糊协作转化为共同目标、唯一责任人与可追踪承诺。

## 沟通核心动作
1. **目标一致**
2. **责任清晰**
3. **执行闭环**

## 沟通流程
1. 先复述共同成功标准，不说“你就应该帮我”。
2. 明确交付物、负责人、依赖、截止时间和资源约束。
3. 复述双方确认的安排，约定异步更新频率与风险升级机制。

## 对方反问时，如何回应
- “我没空”：先了解负荷，再讨论优先级和最小可交付物。
- “这不是我工作”：查询职责边界，不在群内给人贴标签。
- “已经说过了”：用文档和确认回路消除不同理解。

## 安全与伦理底线
不要代替有权者强行分配资源；保留书面记录，不拿隐私数据换取效率。

## 课堂练习组织
- 先读背景和开场，学习者用 20–40 秒尝试自然回应。
- 后续依照案例的 `roundCount` 逐轮播放对方追问，每轮都等待学习者回应；一轮题不添加额外问题。
- 随轮次推进具体的质疑、新约束和边界，而不是使用固定的“第三轮模板”。
- 结束（复盘）：四维自评，每维 0–25 分；着重分析具体句子，不夸大“口才训练”效果。
- 改写（迁移）：同一情境先分别用温和、坚定、简洁三种语气表达，内容保持真实。

## 在仓库中读取案例
- 单题内容源：`data/entries/collaboration/<case-id>.json`
- 结构化卡片：`data/cases/collaboration.json`
- 当前题量：30；难度、标签、轮次由每题元数据独立指定，不能由 ID 推断
- 数据格式和新增流程：`data/README.md`

## 理论延伸
Closed-loop / RACI。参考：https://www.ahrq.gov/hai/cusp/modules/implement/teamwork.html

研究框架需要适应具体关系、文化和安全条件。不要把“让对方同意”当作训练唯一成功标准。
