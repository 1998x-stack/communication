# 案例与扩展规范

源数据在 `data/seeds/{category}.txt`，每行以 `|` 分隔 7 列：标题、背景、对方开场、首次反问、再次追问、期望行动、已知事实。避免在字段内部使用竖线。生成后的规范训练卡位于 `data/cases/*.json`，由 `npm run generate` 输出，页面读取 `data/catalog.json` 自动注册类别与案例。

初始 9 个场景，每类 30 例：1–10 基础、11–20 进阶、21–30 高压，总计 270 例 / 每例 6 个对话轮次和 3 个训练步骤。

## 新增案例

1. 在对应 `data/seeds/*.txt` **追加**一行 7 列；不要修改已发布案例的 ID 顺序，也不要在中间插入或删除行（会改变已有序号与进度）。
2. `npm run build` 重新生成并校验；生成器自动更新各类数量和总数。
3. 若已有案例需要更自然的三轮参考回应，将独立覆盖写入 `data/overrides/{case-id}.json`；构建时自动合并，不能修改 `id`、`difficulty` 或真实事实。
4. 通过 PR 审核敏感信息、清晰度、尊重与安全优先原则。

## 设计原则

学习者的答案不要求与示范逐字一致；示范用来观察结构、提问和对抗压力下的响应。不得收录可识别的真实个人、公司机密或未经授权对话。涉及危机的练习以现实安全支持优先，不提供危险关系中强行和解的建议。

## 未来演进

后续可以增加 schemaVersion 2，支持场景自定义分支树、人工点评、多种参考话术与 ChatGPT 导入；迁移时保持稳定 `id`，使用版本化转换而不是直接破坏旧条目。
## 人工精修覆盖层（已启用）

文件名必须是已存在的稳定案例 ID，例如 `data/overrides/upward-001.json`。允许四个字段：`id`、`responses`（必填，长度恰好为3的非空字符串数组）、`steps`（可选，三段教学步骤）、`focus`（可选，复盘重点）。

```json
{
  "id": "upward-001",
  "responses": [
    "第一轮：先交代有根据的结论和建议。",
    "第二轮：正面回应对方反问，补充必要事实和边界。",
    "第三轮：提出可执行动作与需要谁拍板。"
  ],
  "focus": "关注事实、取舍与决策请求是否衔接。"
}
```

示例仅说明格式，不代替真实案例话术。生成器会验证字段、三轮长度、文件名与 ID 一致，并拒绝不存在的案例；`npm test` 会验证已生成内容和精修源一致。禁止把真实用户隐私和未经授权的课程原文加入公开仓库。新增题目仍应**只向种子末尾追加**，旧题纠错可保持 ID 不变而修改对话内容。

## 初始题库编辑覆盖情况（2026-11-10）

九个类别中每个 `001` 至 `030` 案例都已有 `data/overrides/<case-id>.json`，包含针对实际开场、第一次反问、第二次追问的三段独立话术和 `focus`。共 270 个覆盖文件、810 段参考回应；重新构建保持稳定 ID。未来追加 `031` 及以后编号的题目时允许先生成草稿，但不能据此声称该新题已人工精修。具体质量清单及尚待外部验证的范围见 [逐题精修验收说明](../docs/CURATION_REVIEW.md)。
